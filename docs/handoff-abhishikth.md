## 2. Graph Provenance Relationships

Every `Chunk` node connects directly to its parent entity:
- `(:Chunk {id: "chunk:commit:8fae2:0"}) -[:FROM_COMMIT]-> (:Commit {id: "commit:8fae2"})`
- `(:Chunk {id: "chunk:doc:ADR-7:0"}) -[:FROM_DOCUMENT]-> (:Document {id: "doc:ADR-7"})`
- `(:Chunk {id: "chunk:doc:architecture-overview:0"}) -[:FROM_DOCUMENT]-> (:Document {id: "doc:architecture-overview"})`
- `(:Chunk {id: "chunk:doc:runbook-payment-latency:0"}) -[:FROM_DOCUMENT]-> (:Document {id: "doc:runbook-payment-latency"})`
- `(:Chunk {id: "chunk:issue:PAY-42:0"}) -[:FROM_ISSUE]-> (:Issue {id: "issue:PAY-42"})`
- `(:Chunk {id: "chunk:message:payment-perf-7:0"}) -[:FROM_MESSAGE]-> (:Message {id: "message:payment-perf-7"})`

Direction is always `(Chunk) -[:FROM_*]-> (Source)`.

## 3. Exact Retrieval Interface (`find_sources`)

Module: `weave_data/retrieval.py`
Function signature:
```python
def find_sources(
    source_ids: Iterable[str] | None,
    data_dir: Path | None = None,
    chunks: list[ChunkRecord] | None = None,
    records: list[BaseRecord] | None = None,
    adapter: GraphAdapter | None = None,
) -> list[SourceRecord]:
```

### Deterministic Retrieval Contract
- **Input:** list of canonical source IDs (e.g. `["issue:PAY-42", "doc:ADR-7", "doc:architecture-overview"]`).
- **Graph-backed mode (`adapter` provided):** queries persisted `Chunk` nodes and `FROM_*` edges directly using `adapter.get_chunks_for_sources()`. Never falls back to local disk files when adapter is supplied.
- **Local mode (`adapter=None`):** parses `data/novapay` records and chunks.
- **Output:** list of `SourceRecord` objects containing:
  - `id`: canonical entity ID
  - `type`: source entity type (`Issue`, `Document`, `Commit`, `Message`)
  - `title`: human-readable title
  - `snippet`: verbatim snippet text from stored chunks
  - `url`: web URL if available
  - `chunk_ids`: list of contributing chunk IDs
  - `timestamp`: source timestamp
  - `chunks`: list of underlying `ChunkRecord` models

### Example Retrieval Output
```python
from weave_data.retrieval import find_sources

sources = find_sources(["doc:architecture-overview", "doc:runbook-payment-latency"])
# sources[0].id == "doc:architecture-overview"
# sources[0].title == "NovaPay Core Architecture Overview"
# sources[0].chunk_ids == ["chunk:doc:architecture-overview:0"]
# sources[0].timestamp == datetime(2026, 5, 1, 12, 0, tzinfo=timezone.utc)
# sources[1].id == "doc:runbook-payment-latency"
# sources[1].title == "Runbook: Payment Service Latency & Degradation"
# sources[1].chunk_ids == ["chunk:doc:runbook-payment-latency:0"]
# sources[1].timestamp == datetime(2026, 5, 22, 10, 0, tzinfo=timezone.utc)
```

## 5. Unsupported-Question Expectations (Grounding & Refusal)

Target unsupported question:
> **"Why did NovaPay choose MongoDB for the fraud service?"**

Data guarantee:
1. No node or property in the dataset or graph mentions `MongoDB` or `fraud service`.
2. No decision exists introducing MongoDB or affecting a fraud service.
3. No aliases exist for MongoDB or fraud.
4. Calling `find_sources(["tech:mongodb", "service:fraud-service"])` deterministically returns `[]`.
5. The LLM agent should inspect the retrieved sources/subgraph and issue a grounded refusal stating insufficient evidence exists in the organizational graph.
