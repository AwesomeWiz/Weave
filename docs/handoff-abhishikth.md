## 1. Final Chunk Schema & ID Conventions

All text chunks are generated by `weave_data/chunks.py` as Pydantic models (`ChunkRecord`) with zero-based indexing and full metadata:

| Field | Type | Description | Example |
|---|---|---|---|
| `id` | `str` | Canonical Chunk ID (`chunk:{source_id}:{chunk_index}`) | `chunk:issue:PAY-42:0` |
| `source_id` | `str` | Canonical ID of source entity node | `issue:PAY-42` |
| `source_type` | `str` | Source entity type (`Issue`, `Message`, `Commit`, `Document`) | `Issue` |
| `chunk_index`| `int` | Zero-based index within the source entity | `0` |
| `title` | `str` | Human-readable title or subject line | `Reduce payment latency under burst traffic` |
| `text` | `str` | Verbatim text content (never fabricated) | Full issue description & acceptance criteria |
| `timestamp` | `datetime` | Original ISO-8601 creation/update timestamp | `2026-05-11 09:00:00+00:00` |
| `url` | `str \| None` | Web link to original source record | `https://jira.novapay.example/browse/PAY-42` |

## 2. Graph Relationship Conventions

Every Chunk node is connected to its canonical source node with a typed edge in the knowledge graph:

- `(:Chunk {id: "chunk:issue:PAY-42:0"}) -[:FROM_ISSUE]-> (:Issue {id: "issue:PAY-42"})`
- `(:Chunk {id: "chunk:message:payment-perf-7:0"}) -[:FROM_MESSAGE]-> (:Message {id: "message:payment-perf-7"})`
- `(:Chunk {id: "chunk:commit:8fae2:0"}) -[:FROM_COMMIT]-> (:Commit {id: "commit:8fae2"})`
- `(:Chunk {id: "chunk:doc:ADR-7:0"}) -[:FROM_DOCUMENT]-> (:Document {id: "doc:ADR-7"})`

In `run_ingestion()`, source entity nodes and chunk nodes are persisted before relationships are created, guaranteeing that all relationship endpoints exist.

## 3. Exact Source Retrieval Interface (`find_sources`)

Module: [`weave_data/retrieval.py`](file:///c:/Users/alena/OneDrive/Desktop/Weave/Weave/weave_data/retrieval.py)  
Exported from: `weave_data`

### Function Signature
```python
def find_sources(
    source_ids: Iterable[str] | None,
    data_dir: Path | None = None,
    chunks: list[ChunkRecord] | None = None,
    records: list[BaseRecord] | None = None,
    adapter: GraphAdapter | None = None,
) -> list[SourceRecord]:
    ...
```

### Retrieval Modes

1. **Graph-Backed Mode (`adapter` provided):**
   - Retrieves persisted `Chunk` nodes and their `FROM_*` edges directly from graph storage via `adapter.get_chunks_for_sources(requested_ids)`.
   - Supports both `InMemoryGraphAdapter` and `FalkorDBGraphAdapter`.
   - Executes parameterized Cypher in FalkorDB:
     ```cypher
     MATCH (c:Chunk)-[r]->(s)
     WHERE s.id IN $source_ids AND type(r) IN ['FROM_ISSUE', 'FROM_MESSAGE', 'FROM_COMMIT', 'FROM_DOCUMENT']
     RETURN s.id AS source_id, type(r) AS rel_type, c.id AS id, c.source_type AS source_type, c.chunk_index AS chunk_index, c.title AS title, c.text AS text, c.timestamp AS timestamp, c.url AS url
     ORDER BY c.chunk_index ASC
     ```
   - Operates entirely independent of local disk files. Works seamlessly even when `data/` files are absent or during remote deployments.

2. **Local Fallback Mode (`adapter is None`):**
   - When no adapter is provided, falls back to memory chunks or parses local disk files in `data_dir` (`data/novapay` by default).
   - Preserves 100% backwards compatibility with existing offline tests and scripts.

### Adapter Construction & Passing Example

```python
from weave_data.retrieval import find_sources
from weave_data.graph_adapter import FalkorDBGraphAdapter, InMemoryGraphAdapter

# In production with FalkorDB:
adapter = FalkorDBGraphAdapter(host="localhost", port=6379, graph_name="novapay")
sources = find_sources(["doc:ADR-7", "issue:PAY-42"], adapter=adapter)

# In test environments:
test_adapter = InMemoryGraphAdapter()
# (ingestion runs with test_adapter)
sources = find_sources(["doc:ADR-7", "issue:PAY-42"], adapter=test_adapter)

# Local fallback (no adapter):
sources = find_sources(["doc:ADR-7", "issue:PAY-42"])
```

### Output Structure (`SourceRecord`)
```python
class SourceRecord(BaseModel):
    id: str                    # Canonical entity ID (e.g. "issue:PAY-42")
    type: str                  # Source entity type (e.g. "Issue")
    title: str                 # Document/Ticket/Thread title
    snippet: str               # Verbatim text snippet from contributing chunks
    url: Optional[str] = None  # Direct link
    chunk_ids: list[str]       # Contributing chunk IDs (e.g. ["chunk:issue:PAY-42:0"])
```

### Deterministic Retrieval Properties
- **Exact resolution:** Looks up evidence by canonical source ID.
- **Deduplication:** Repeated input IDs return exactly one `SourceRecord`.
- **Multi-chunk aggregation:** If a source has multiple chunks (e.g. `chunk:doc:ADR-7:0`, `chunk:doc:ADR-7:1`), their texts are assembled in `chunk_index` order, and all chunk IDs are tracked in `chunk_ids`.
- **Unknown sources:** Non-existent IDs return `[]` without error.
- **Empty input:** `None`, `[]`, or `[""]` immediately return `[]`.
- **No hallucination:** Never fabricates or synthesizes text; uses verbatim persisted chunk text.

### Realistic Sample Usage & Output
```python
from weave_data.retrieval import find_sources

# Graph-backed retrieval:
sources = find_sources(["doc:ADR-7", "issue:PAY-42"], adapter=adapter)
for s in sources:

    print(f"Chunks: {s.chunk_ids}")

```
